## Why this matters

presentational (a `<kbd>` with platform-aware key symbols), so it needs NO
core primitive — all logic lives in the React component.

### Reference implementation (old system: `/Users/raminrezaei/Documents/Projects/Personal/hashti/packages/react/src/components/kbd/`)

Read it before writing. Facts:

- `Kbd` renders `<kbd class="hashti-kbd">`. Props: `keys?: string | string[]`
  (renders one `<span class="hashti-kbd-key">` per key, platform-formatted)
  or `children` (raw content, no formatting).
- `formatKey(key, isMac)`: trims/lowercases; MAC_SYMBOLS map
  (command/cmd/meta/mod → ⌘, shift → ⇧, ctrl/control → ⌃, option/alt → ⌥,
  enter/return → ↵, backspace → ⌫, delete → ⌦, escape/esc → Esc, tab → ⇥,
  capslock → ⇪, arrows up/down/left/right → ↑↓←→); WIN_SYMBOLS maps the
  same names to text (Ctrl, Shift, Alt, Enter, Backspace, Del, Esc, Tab,
  Caps, arrows). Single characters uppercase; unknown multi-char keys pass
  through as-is.
- Platform detection: `navigator.userAgentData?.platform ?? navigator.platform
  ?? navigator.userAgent`, tested against `/mac|iphone|ipad|ipod/i`,
  defaulting to Mac (SSR renders Mac symbols — acceptable, note it).
- Copy the maps and `formatKey` verbatim into the new component (they are
  the extracted behavior); do not redesign them this cycle.

### Design rules that bite (from the old stylesheet, tokenized for hashti-new)

- `.hashti-kbd`: inline-flex, centered, `min-height: 1lh`,
  `min-width: 1.5rem`, `padding: 0.125rem 0.375rem`, border `1px solid
  var(--hashti-border-strong-01)` with `border-block-end-width: 2px` (the
  keycap press depth), `border-radius: var(--hashti-border-radius-04)`
  (0.25rem — tokenized; the old 3px rounds to the nearest token),
  background `var(--hashti-layer-01)`, ink `var(--hashti-text-primary)`,
  font `var(--hashti-label-01-font-size)` (0.75rem) weight 500,
  `line-height: 1rem`, `white-space: nowrap`.
- `.hashti-kbd + .hashti-kbd { margin-inline-start: 0.25rem; }` — adjacent
  keycaps separate themselves (no wrapper needed for combos).
- `.hashti-kbd-key`: no extra styling beyond inheritance (spans for
  spacing between keys of one Kbd — give them `margin-inline-end: 0.125rem`
  except the last via `.hashti-kbd-key:last-child { margin-inline-end: 0; }`).
- Colours only via `var(--hashti-*)`; a hex in component CSS is a bug.
- No focus ring (Kbd is not interactive).
